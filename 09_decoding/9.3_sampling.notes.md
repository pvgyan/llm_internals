## temperature + top_p 采样

Q: 这个页面 https://yeasy.gitbook.io/llm_internals/di-san-bu-fen-tui-li-yu-bu-shu-pian/09_decoding/9.3_sampling, 讲了 temperature + top_p 采样的大致思想， 我的问题是 temperature + top_p 采样 只是做了 概率值的 调整。  那调整之后，是 选最大的哪个吗？ 还是说在 剩余的非0 中 随机选择1个 或 N个？  我在 这块原文 都没有看到.

A: 你的直觉是对的：**temperature / top_k / top_p 只是"改造概率分布"，不是最后一步的选择动作**。 原文如果没写最后一步，那是它默认你已经知道：*改造完分布后，还要再"抽一次"*。

---

## 一、完整流水线（每一步在干啥）

对当前位置，模型输出 `logits`（长度 = vocab_size）：

1. **temperature**
   $$
   z_i' = z_i / T
   $$
   只改变分布形状，不决定选谁。

2. **softmax**
   $$
   p_i = \text{softmax}(z'/T)_i
   $$

3. **top_k / top_p 过滤**
   - top_k：只保留概率最高的 k 个
   - top_p：从大到小累加，保留累计概率 ≥ p 的最小集合
   - 其余 token 概率置 0

4. **对保留集合重新归一化**
   $$
   \hat p_i = \frac{p_i}{\sum_{j\in \text{survivors}} p_j}
   $$

5. **最后一步：从这个分布里抽 1 个 token**
   - 不是"选最大的"
   - 也不是"把所有非 0 的都输出"
   - 而是：**按 $\hat p$ 做多项式随机采样（multinomial sampling），得到 1 个 token**

---

## 二、三种最终动作对照

| 配置 | 最后一步 |
|---|---|
| `temperature=0` / `top_k=1` / `do_sample=False` | **argmax**：选概率最大的那个 |
| `temperature>0` + top_k/top_p | **随机采样 1 个**：按剩余分布抽 |
| beam search | 同时维护 B 条序列，不选"1 个 token"，而是扩展 + 剪枝 |

所以：

> temperature + top_p 之后 → **在剩余非 0 的 token 中，按概率随机选 1 个**
> 最高概率的 token 只是"最可能被抽到"，但不保证一定被抽到。

---

## 三、一个小例子

假设过滤 + 归一化后剩 3 个 token：

```
巴黎   0.70
里昂   0.20
马赛   0.10
```

下一步会：

- 生成随机数 $r \in [0,1]$
- 累计：
  - $r < 0.70$ → 巴黎
  - $0.70 \leq r < 0.90$ → 里昂
  - $r \geq 0.90$ → 马赛

每次生成都不一样（除非 temperature=0）。

## 四、为什么原文"没写"这点

这类书/文档常把重点放在：

- temperature 怎么锐化/拉平分布
- top_p 怎么动态截尾

而把最后一步当成常识：

> "得到合法概率分布后，采样（sample）一个 token。"

代码里就是一行：

```python
next_token = torch.multinomial(probs, num_samples=1)
```

或者等价地：

```python
if temperature == 0:
    next_token = argmax(logits)
else:
    next_token = multinomial(softmax(filtered_logits / T))
```

---

## 一、完整流程（五步走）

1. **Temperature 缩放**
   $$
   z_i' = z_i / T
   $$
   拉平或锐化分布。

2. **Softmax**
   得到原始概率分布 $p_i$。

3. **Top-p 过滤**
   按概率从大到小排序，累加直到超过阈值 p，只保留这批 token，其余概率置 0。

4. **重新归一化**
   对保留的 token 的概率做归一化，使它们之和为 1。

5. **随机采样 1 个**
   从这一步的分布中做多项式采样（multinomial sampling），**抽出一个 token**。

---

## 二、三种最终选择方式对比

| 方式 | 最后一步 | 输出个数 |
|---|---|---|
| **Greedy（T=0 / do_sample=False）** | argmax，选概率最大的那个 | 1 个 |
| **Temperature + Top-p（T>0）** | 按概率随机采样 | **1 个** |
| **Beam Search** | 扩展 B×V 个候选 → 剪枝留 B 条序列 | B 条序列，每步不是选 1 个 token |

所以你关心的那种情况：**temperature + top_p 之后，是在剩余的非零 token 中，按它们各自的概率随机选 1 个。** 概率大的更容易被抽到，但不保证一定被抽到。

---

## 三、为什么不是选最大的

如果调整完分布后还是选最大的，那 temperature 和 top_p 就失去了意义：

- Temperature 拉平分布后，原本概率低的 token 有机会被选中，增加了多样性
- Top-p 去掉尾部噪声后，在头部合理范围内随机，既避免低质 token 又不至于完全确定

如果最后一步改成 argmax，那无论你怎么调 temperature，结果都和 greedy decoding 一样——白调了。

## 四、代码层面的对应

```python
# 调整分布
scaled_logits = logits / temperature
probs = F.softmax(scaled_logits, dim=-1)

# top-p 过滤
sorted_probs, sorted_indices = torch.sort(probs, descending=True)
cumsum = torch.cumsum(sorted_probs, dim=-1)
mask = cumsum - sorted_probs > top_p  # 保留累计概率刚超过 p 的最小集合
sorted_probs[mask] = 0.0
probs = sorted_probs / sorted_probs.sum()  # 重新归一化

# 最后一步：采样 1 个
next_token = torch.multinomial(probs, num_samples=1)
```

关键就在最后一行：`torch.multinomial(probs, num_samples=1)`，不是 `probs.argmax()`。
