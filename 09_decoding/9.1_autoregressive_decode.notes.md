是的，你说的对，"批量生成"就是指同时处理多条序列。左填充的必要性源于**因果注意力掩码**的工作机制。

---

## 一、问题场景

假设你要同时给两条 prompt 生成续写：

```
序列 A: "今天天气"     （长度 4）
序列 B: "人工智能正在" （长度 5）
```

为了组成一个 batch，短的序列需要填充到与最长序列相同的长度。

---

## 二、右填充的问题

如果采用**右填充**（pad token 放在右边）：

```
序列 A: ["今天", "天气", <pad>, <pad>, <pad>]
序列 B: ["人工", "智能", "正在", <pad>, <pad>]
```

因果注意力掩码的作用是：**每个 token 只能看到自己和左边的 token**。

对于序列 A 的第一个 `<pad>`（位置 2），它的注意力范围是 `["今天", "天气", <pad>]`。模型会学到"看到 `<pad>` 时预测下一个 token"，但真正的序列 A 在位置 2 之后已经没有有效 token 了——然而由于 `<pad>` 在右边，位置 2 的 `<pad>` 仍然能看到位置 0 和 1 的有效内容，导致它产生有意义的预测输出。这个输出会被当作序列 A 的生成结果，但实际上它是无效的填充位产生的垃圾内容。

---

## 三、左填充的解决方案

采用**左填充**（pad token 放在左边）：

```
序列 A: [<pad>, <pad>, <pad>, "今天", "天气"]
序列 B: [<pad>, <pad>, <pad>, <pad>, "人工智能正在"]  （实际按 token 拆分）
```

更准确的写法是按 token 级别：

```
序列 A: [<pad>, <pad>, <pad>, "今天", "天气"]
序列 B: [<pad>, "人工", "智能", "正在", "发展"]
```

现在看最后一个位置（位置 4）：
- 序列 A 的最后一个 token 是 `"天气"`，它能看到左边的所有有效 token `[<pad>, <pad>, <pad>, "今天"]`。由于 `<pad>` 的嵌入向量通常为零或特殊值，对注意力计算的贡献很小，模型主要基于 `"今天"` 来预测下一个词。
- 序列 B 的最后一个 token 是 `"发展"`，它能看到的左边内容是 `[<pad>, "人工", "智能", "正在"]`，同样 `<pad>` 干扰很小。

**关键点**：所有序列的有效 token 都**对齐到右侧**，这样每个序列的最后一个有效 token 都在 batch 中的同一位置，便于一次性采样下一个 token。

---

## 四、一句话总结

| 填充方式 | 问题 |
|---|---|
| 右填充 | `<pad>` 在有效 token 之间，会被因果注意力当成有效输入，产生垃圾预测 |
| 左填充 | `<pad>` 在最左侧，因果注意力让它们只参与很少的计算，有效 token 右对齐，输出位置整齐 |

[End]

## Q: 序列A 和B这样的batch输入，会组织成怎样的tensor输入给 LLM ？
例如： 按 token 级别：
序列 A: [<pad>, <pad>, <pad>, "今天", "天气"]
序列 B: [<pad>, "人工", "智能", "正在", "发展"]
对于序列A，做了 tokenization & embedding 之后，它应该是 一个  5xd_model 的 matrix。  5表示 5个token， d_model为嵌入维度为。

A: 你说得对。序列 A 和 B 经过 tokenization 和 embedding 后，各自得到一个形状为 `(5, d_model)` 的矩阵。将它们组成一个 batch 输入给 LLM 时，tensor 的组织方式是：

---

## 最终输入 Tensor

**形状：`(batch_size=2, seq_len=5, d_model)`**

```
batch_input[0] = 序列 A 的 embedding:
[
  [embedding of <pad>],      // 位置 0
  [embedding of <pad>],      // 位置 1
  [embedding of <pad>],      // 位置 2
  [embedding of "今天"],     // 位置 3
  [embedding of "天气"]      // 位置 4
]

batch_input[1] = 序列 B 的 embedding:
[
  [embedding of <pad>],      // 位置 0
  [embedding of "人工"],     // 位置 1
  [embedding of "智能"],     // 位置 2
  [embedding of "正在"],     // 位置 3
  [embedding of "发展"]      // 位置 4
]
```

**维度解释：**
- 第 0 维（batch 维）= 2，代表两条序列
- 第 1 维（seq_len 维）= 5，代表每条序列的长度（已填充对齐）
- 第 2 维（hidden 维）= d_model，代表每个 token 的嵌入向量

---

## 配套的 Attention Mask

LLM 还需要一个 **attention mask** 来告诉模型哪些位置是有效的、哪些是 padding。形状为 `(batch_size, 1, seq_len, seq_len)`：

```
mask[0] = 序列 A 的因果 + padding 掩码:
[
  [0, 0, 0, 0, 0],    // <pad> 看不到任何位置（或被设为 -inf）
  [0, 0, 0, 0, 0],    // <pad>
  [0, 0, 0, 0, 0],    // <pad>
  [0, 0, 0, 1, 0],    // "今天" 只看自己
  [0, 0, 0, 1, 1]     // "天气" 看自己和"今天"
]

mask[1] = 序列 B 的因果 + padding 掩码:
[
  [0, 0, 0, 0, 0],    // <pad>
  [0, 1, 0, 0, 0],    // "人工" 只看自己
  [0, 1, 1, 0, 0],    // "智能" 看自己和"人工"
  [0, 1, 1, 1, 0],    // "正在" 看前面三个
  [0, 1, 1, 1, 1]     // "发展" 看所有有效 token
]
```

其中 1 表示允许关注，0 表示不允许（实际实现中用 0 和 -inf 来表示）。

---

## 自回归生成时的流程

第一次前向传播后，模型输出 logits 形状为 `(2, 5, vocab_size)`。取**每个序列最后一个有效 token** 对应的 logits：

- 序列 A：取位置 4（"天气"）的输出 → 采样得到下一个 token，比如 "真"
- 序列 B：取位置 4（"发展"）的输出 → 采样得到下一个 token，比如 "迅"

然后将新 token 拼接到末尾，更新 batch：

```
序列 A: [<pad>, <pad>, <pad>, "今天", "天气", "真"]
序列 B: [<pad>, "人工", "智能", "正在", "发展", "迅"]
```

重复这个过程，直到所有序列都生成结束或达到最大长度。
